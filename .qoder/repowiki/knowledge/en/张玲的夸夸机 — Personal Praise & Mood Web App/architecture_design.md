Static frontend (index.html, history.html, push.html, zhangling.html) served directly from the repository root, with a service worker `sw.js` handling Web Push events (`push`, `notificationclick`). Serverless functions live under `functions/api/`, one file per feature: content generation (`aiquote.js` calls DeepSeek via `env.DEEPSEEK_API_KEY`), state/metrics (`count.js`, `visit.js`, `track.js`, `mood.js`, `cd_state.js`, `prizes.js`, `lottery520.js`, `whack_play.js`, `monthly_report.js`, `dog_name.js`, `jar.js`, `ielts_progress.js`, `note.js`), and push infrastructure (`push-subscribe.js` stores subscriptions in KV under `push_subscriptions`; `push-send.js` implements RFC 8291 encryption + RFC 8292 VAPID signing to broadcast to all stored endpoints). The frontend pages call these endpoints via `fetch('/api/...')`. KV bindings are injected at runtime through `env.ZHANGLING_MOOD_KV`; secrets come from `env.DEEPSEEK_API_KEY`, `env.PUSH_SECRET`, `env.VAPID_PUBLIC_KEY`, `env.VAPID_PRIVATE_KEY`. All API handlers export `onRequestOptions` / `onRequestGet` / `onRequestPost` and attach a shared CORS header set, making them compatible with Cloudflare Workers routing.
